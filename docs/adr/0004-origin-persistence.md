# 0004: 起点の永続化方式

## ステータス

**保留（2026-08-05）。要検証。**
US-07 の実装に着手する前にスパイクを1本走らせて決める。

**この ADR は「まだ決まっていない」ことを記録するために先に置く。**
方式が未確定なまま実装に入って、後から構造を作り替えるのを避けるため、
境界（ポート）だけ先に決めて実装を差し替え可能にした（design.md 8節）。

## 背景

2回目以降は起点を指定せずに使いたい（US-07）。

- **AC-07-1** 起点を指定すると、その座標がブラウザに保存される
- **AC-07-2** 次回アプリを開いたとき、保存された起点が復元され地図上に表示される
- **AC-07-3** 復元された起点は、地図をクリックすることで上書きできる
- **AC-07-4** 保存された起点がない初回起動時は、起点の指定を促す状態で表示される

**`st.session_state` は使えない。** Streamlit のセッション状態は
ブラウザを閉じると消えるため、AC-07-2 を満たさない（CLAUDE.md の注意点）。
「セッションを超えて復元する」ことが US-07 の要求である。

**requirements.md 4.7 が明示しているとおり、この US には実測の裏付けがない。**
ORS のスパイクは4本走らせたが、ブラウザ側の永続化はスパイク未実施である。
他の要件が実測に紐づいているのに対し、ここだけ何も測っていない。

## 検討している選択肢（いずれも未検証）

| # | 方式 | 追加依存 | 主な未確認点 |
|---|---|---|---|
| 1 | ブラウザの localStorage（コンポーネント経由） | **あり**（`streamlit-local-storage` 等） | 初回描画で値が返るか。パッケージの保守状況。iOS Safari での保持 |
| 2 | URL のクエリパラメータ（`st.query_params`） | なし | **自宅座標が URL に載る**。ブックマーク／ホーム画面追加が前提になる |
| 3 | Cookie | 読み出しは標準機能でできる見込み。**書き込みにはコンポーネントが必要** | 書き込み手段。有効期限。iOS の Cookie 制限 |
| 4 | サーバ側のファイル | なし | 「ブラウザに保存」という要件から外れる。Streamlit Community Cloud では再起動で消える |

### 各方式についての現時点の見方

**1. localStorage —— 要件に最も素直。第1候補。**
「ブラウザに保存」をそのまま実現する。懸念は2つ。
①依存パッケージの追加になり、CLAUDE.md により事前の確認が必要。
②Streamlit のカスタムコンポーネントは、値がブラウザから返るまで
`None` を返す場合がある（スクリプトが再実行されて初めて値が入る）。
これが AC-07-2 の「次回開いたときに復元される」体験にどう影響するかは**要検証**。

**2. クエリパラメータ —— プライバシー上の懸念が大きい。**
追加依存なしで実装できるが、保存する座標は**自宅**である。
URL に載ると、ブラウザ履歴・共有・スクリーンショットで漏れる。
スパイクの生データで座標を記録しなかったのと同じ理由で、
この方式は積極的には採らない。

**3. Cookie —— 書き込み手段が課題。**
読み出しは Streamlit の標準機能でできる見込みだが（**要確認**）、
書き込みにはコンポーネントが必要で、結果として方式1と同じ依存追加の話になる。

**4. サーバ側ファイル —— 要件から外れる。**
個人利用なら成立しそうに見えるが、AC-07-1 は「ブラウザに保存」と定めている。
また Streamlit Community Cloud（公開先の想定。WORKFLOW.md フェーズ7）は
コンテナが再起動するとファイルが消えるため、そもそも永続しない。

## 決めるために確かめること（スパイクの計画）

| # | 確認すること | なぜ必要か |
|---|---|---|
| 1 | 方式1で、アプリを開き直したときに保存値が復元されるか | AC-07-2 そのもの |
| 2 | 初回描画で値が取れるか。取れない場合、画面がどう見えるか | 「一瞬だけ未設定の画面が出る」なら AC-07-4 と混ざる |
| 3 | iPhone の Safari で、ホーム画面に追加した状態で保持されるか | 利用状況の前提（requirements 4.3） |
| 4 | プライベートブラウズやサイトデータ削除で消えたときの挙動 | 消えたら初回起動と同じ状態になるべき（AC-07-4） |
| 5 | 追加パッケージの保守状況（更新の新しさ、Streamlit 1.60 での動作） | 依存を増やす判断の材料（CLAUDE.md） |

**このスパイクは ORS の無料枠を消費しない。** ブラウザ側だけの検証である。

## 保留中の実装方針

`persistence.py` に読み書きのポートだけ定義する（design.md 8.1）。

```
OriginStore（Protocol）
    load() -> LatLon | None
    save(origin: LatLon) -> None
    clear() -> None
```

- 当面はセッション内だけで保持する実装（＝実際には永続化しない）を置く
- `ui/app.py` はこの Protocol にしか触らない
- **AC-07-1〜4 は未達であることを明示する。** 黙って満たしたことにしない
- US-07 は実装タスクの最後に回す（他の US はこれに依存しない）

**理由:** 未検証の方式を先に入れると、その方式の制約（初回描画で値が返らない等）が
画面全体の構造に染み出す。ポートを固定しておけば、決定後の変更は
`persistence.py` の実装1つと、依存の追加だけに収まる。

## どの方式でも守ること

- **座標を URL・ログ・エラーメッセージに出さない。** 保存対象は自宅である
- **座標を丸めない。** AC-05-1 は「自宅の玄関を正確に起点にしたい」であり、
  プライバシーのための丸めは要件と衝突する。保存場所を選ぶ側で守る
- 保存する起点は1件のみ（複数の起点の登録はスコープ外。requirements 3.2）
